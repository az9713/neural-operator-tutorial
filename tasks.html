The procedure, the same for each one

  1. Write the script in the matching labs/ folder. Fix and record the seed.
  2. Run it. Write the numbers to a results*.json in that folder.
  3. Run it a second time. A single seed is not a result: runs are not bit-reproducible on CUDA, and run A gave 0.0040 and 0.0044 on two runs.
  4. Edit the module page. Replace the "not yet run" text with the measured numbers and a LAB grade.
  5. Check the page renders, then commit and push. Wait for the Pages build before you report a status code.

Modules 0, 1, 2, 5, 6, 8, 12 and 14 all treat the first lab's question as unsettled. One inference run changes eight pages, which is why it is first and not merely cheapest.

Rules that apply to every task above

  1. Every number must trace to a line in research_notes/, a page of a source PDF, or a lab results file. Write "not yet run" instead of an invented figure. Never repair a citation from memory.
  2. This folder is public. Before any commit, confirm that no personal path, hostname or email address entered a tracked file.
  3. Four things stay out of git: .ignore/, the resume file, the source PDFs, and labs/02_thermal/thermal_data.pt, which is 601 MB and over the GitHub file limit. Regenerate the thermal data with its own script.
  4. Never write TeX through a shell heredoc. The escape sequences collapse into control bytes, and \bar and \varepsilon become 0x08 and 0x0b. Use a file-writing tool or a Python script. This has damaged the project twice.
  5. Read your own prose before calling a writing task done. A mechanical check passes control bytes, delimiters, tags, links and numbers, and says nothing about whether the sentences read as human writing. Read every table-driven replacement in its full sentence before committing it.
  6. Delete nothing.
