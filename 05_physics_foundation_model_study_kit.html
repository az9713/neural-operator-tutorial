The claim worth studying

Hypothesis: a model pretrained on multiple compatible physical systems learns reusable structure—such as transport, diffusion, conservation, and multiscale behavior—so it needs less data to learn a held-out system than an equally sized model trained only on that held-out system.

This is a more exact and more interesting claim than “AI can learn physics.” It can be false. It can also be partly true: transfer may work inside a compatible family of grid-based PDEs yet fail across changing geometry, boundary conditions, constitutive laws, or sensors. That boundary is the research result.

Do not confuse three different objectives. A fast surrogate predicts a known simulator. A PINN uses equations to fit sparse data or infer unknown parameters. A cross-domain foundation model tries to reuse a representation across systems. They overlap, but success in one does not establish success in the others.

Reading path: six items, in this order

1. Fourier Neural Operator

Li et al., 2020. Read first. It explains why an operator maps a whole input field to a whole solution field and why Fourier layers can transfer across grid resolutions. Reproduce its simplest Burgers example before reading anything more ambitious.

2. Neural Operator, formal version

Kovachki et al., JMLR 2023. This is the conceptual backbone: function-space mappings, discretization invariance, and operator parameterizations. Read the introduction and experiments first; return to the theory once you have built an FNO.

3. DeepONet as the alternative factorization

Lu et al., Nature Machine Intelligence 2021. Its branch net represents the input function and its trunk net represents query locations. It is useful when sensor locations or output coordinates vary.

4. Physics-informed neural networks

Raissi, Perdikaris & Karniadakis, JCP 2019. Learn the residual-loss idea and its forward/inverse-problem distinction. Treat PINNs as a baseline or a constraint mechanism, not an automatic replacement for numerical simulation.

5. MeshGraphNets

Pfaff et al., ICLR 2021. Read when regular grids are no longer enough. It is the bridge to irregular finite-element/finite-volume meshes, deforming geometry, and engineering-style simulation.

6. PDEBench

Takamoto et al., NeurIPS 2022. Read this before claiming a new method works. It foregrounds varied PDEs, initial/boundary conditions, inverse and forward tasks, and comparable baselines.

Recommended first project: cross-PDE transfer, not a demo

Name: Operator Transfer Under Physics Shift. It should take three to four focused weeks and produce a result worth keeping even if the hypothesis fails.

01

Build the smallest honest baseline.

Use NeuralOperator to reproduce an FNO on 1D viscous Burgers. Train at 64 grid points; test on both the trained resolution and a finer resolution. Record normalized L2 error, rollout error, runtime, and seed. This tests the operator machinery before any transfer story.

02

Create a compatible two-source curriculum.

Generate or select periodic, grid-based trajectories for 1D Burgers and 1D advection–diffusion. Give the model the initial field, coefficients, time query, and an explicit equation identifier. Keep units and normalization explicit. Do not quietly mix incompatible variables into one channel tensor.

03

Test real transfer on a held-out target.

Choose a target such as a new Burgers viscosity regime for the first test, then an entire related PDE family for the harder test. Pretrain the shared FNO on the source systems, fine-tune on 1%, 5%, 10%, 25%, and 100% of target data, and compare against an equal-capacity from-scratch FNO.

04

Add physics only after the data baseline works.

Add a normalized PDE-residual or conservation penalty. Sweep its weight; report whether it improves out-of-distribution error or merely trades off field accuracy. Automatic differentiation is not proof of physical fidelity.

05

Make the negative result useful.

If transfer fails, vary only one dimension at a time: common grid, equation identifier, shared trunk versus separate heads, coefficient range, and pretraining sample count. The deliverable is a transfer map, not a benchmark victory screenshot.

Evaluation that can actually falsify the claim

Primary outcome

Data efficiency: at each target-data fraction, does pretraining lower target test error over at least several random seeds versus an equal-compute, equal-parameter scratch model?

Resolution and time

Test 64 → 128/256 grid transfer separately from long-horizon rollout. These answer different questions. A good one-step field predictor can still drift catastrophically over time.

Physics diagnostics

Track mass conservation, energy or enstrophy where defined, boundary-condition violation, PDE residual, and stability. Use the numerical solver as the reference, not a visually pleasing animation.

Anti-leakage controls

Split by initial-condition family and coefficient regime, not just random frames from the same trajectory. Hold out a physics family only after you have a well-defined shared input/output representation.

Minimum experiment matrix

A. Scratch FNO → target only B. Multi-task FNO → sources + target jointly C. Pretrain then fine-tune → sources → target D. Pretrain + physics residual → sources → target Hold constant: parameter count, optimizer budget, target data fraction, normalization, solver fidelity, seed count, and evaluation grid.

Failure modes worth looking for: spectral aliasing mistaken for super-resolution; target trajectories leaking into training; an equation token that lets the model memorize instead of transfer; residual losses that dominate scaling; and reporting only a single final-time image rather than rollout and invariant errors.

Where to go after the first result

Semiconductor path

Move from periodic scalar fields to irregular geometry, PDE coefficients tied to materials, and inverse design. The right next tool is likely FEniCS plus a mesh/GNN architecture—not indiscriminate FNO scaling.

Energy/geothermal path

Study coupled transport, heterogeneous media, and uncertainty. Prioritize calibrated uncertainty and parameter inference before expensive closed-loop optimization.

Research contribution path

Publish a clean transfer benchmark with exact solver, splits, seeds, metrics, and negative cases. The field needs evidence about when cross-PDE pretraining transfers, not another generic “physics AI” claim.

Builder path

Turn the trained surrogate into an interactive design explorer only after you establish error bars and rejection rules. A fast wrong simulation is operationally worse than a slow trusted one.
