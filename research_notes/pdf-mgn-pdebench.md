## PART 1 — MeshGraphNets (MGN)

### 1.1 Plain-language summary

MeshGraphNets is a neural network that learns to run physics simulations on meshes — the triangle/tetrahedron grids that engineers already use in finite-element and finite-volume solvers — instead of on regular pixel-like grids. The trick is to think of the mesh as a graph: each mesh node is a graph node, each mesh edge is a graph edge, and a graph neural network passes messages along those edges to guess how the system evolves one time step into the future. Because it operates in two coordinate systems at once — the fixed "mesh space" that encodes the object's own geometry and the moving "world space" that encodes where things actually are in 3D — the model can separately learn "internal" physics (how a material bends or a fluid diffuses along its own surface) and "external" physics (collision and contact between objects that are close in space but far apart on the mesh). The model is trained only to predict one step ahead, but by adding noise to its own inputs during training it becomes robust enough to be run for thousands of steps in a row without blowing up. It also learns to do its own adaptive remeshing — deciding where to add or remove mesh resolution — so it can be trained cheaply on small meshes and then deployed on far larger, more detailed ones. Across four very different physics domains (cloth, hyperelastic plates, and two kinds of fluid flow) it beats grid-based CNNs (U-Net) and simpler graph baselines (GCN, the particle-based GNS method) on accuracy, while running 1–2 orders of magnitude faster than the ground-truth numerical solvers it was trained on. (p.1, abstract)

### 1.2 Key definitions and architecture

**Problem setup (p.3, Section 3).** The simulation state at time *t* is a mesh *M^t = (V, E_M)*: nodes *V* connected by mesh edges *E_M*. Each node *i* has a fixed reference mesh-space coordinate *u_i* (spans the simulation mesh) plus dynamical quantities *q_i* to be predicted. Two system types:
- **Eulerian systems** (fluids: CylinderFlow, Airfoil) — mesh is fixed, *q_i* samples continuous fields (velocity, momentum, density, pressure) at fixed mesh nodes.
- **Lagrangian systems** (cloth, hyperelastic plate) — the mesh itself moves/deforms, so nodes carry an additional world-space coordinate *x_i* in 3D on top of the fixed mesh-space coordinate *u_i*.

**Encode-Process-Decode architecture** (p.3–4, Section 3.1; diagrammed in Figure 1, p.2):

1. **Encoder.** Converts mesh *M^t* into a multigraph *G = (V, E_M, E_W)*.
   - Mesh edges *E_M*: bidirectional, taken directly from the mesh's own connectivity — captures internal dynamics.
   - **World edges *E_W*** (Lagrangian systems only): added by spatial proximity — connect nodes *i, j* whenever |x_i − x_j| < r_W (a fixed radius on the order of the smallest mesh edge length), excluding pairs already connected by a mesh edge. Purpose: let the network pass messages between nodes that are close in 3D space but far apart along the mesh surface — i.e., (self-)collision and contact (Figure 3a, p.4). No world edges exist for Eulerian systems (footnote 1, p.4).
   - **Relative, equivariant feature encoding**: edges carry the *relative* displacement vectors and their norms rather than absolute positions — mesh edges get relative mesh-space displacement *u_ij = u_i − u_j*, |u_ij|, and relative world-space displacement *x_ij*, |x_ij|; world edges get only the world-space relative displacement and norm. All remaining dynamical quantities *q_i* plus a one-hot node-type vector are node features *v_i*. This relative encoding is what gives the model spatial equivariance and is explicitly cited as key to generalization (p.8: "consistent with our hypothesis that the GCN performs worse due to the lack of relative encoding").
   - Everything (nodes, both edge types) is embedded via separate encoder MLPs ε^M, ε^W, ε^V into a 128-dim latent vector each.

2. **Processor.** *L* identical message-passing "GraphNet blocks" (generalizing prior GraphNet blocks to multiple edge sets), applied in sequence, each with its own parameters (p.4, Eq. 1):
   ```
   e'^M_ij ← f^M(e^M_ij, v_i, v_j)
   e'^W_ij ← f^W(e^W_ij, v_i, v_j)
   v'_i    ← f^V(v_i, Σ_j e'^M_ij, Σ_j e'^W_ij)
   ```
   f^M, f^W, f^V are MLPs with residual connections. *L* is a key hyperparameter: the paper finds L=15 is a good accuracy/compute tradeoff (p.9, Figure 5d) — too few message-passing steps hurts accuracy, more steps costs more compute.

3. **Decoder + integrator** (p.4). Decoder MLP δ^V maps the final-layer node latent to one or more output features *p_i*, interpreted as (higher-order) time derivatives of *q_i*, then integrated with **forward Euler, Δt = 1**:
   - First-order systems: q^{t+1}_i = p_i + q^t_i.
   - Second-order systems (cloth, since it tracks position and needs acceleration): q^{t+1}_i = p_i + 2q^t_i − q^{t−1}_i.
   - Some outputs are direct (non-integrated) predictions of auxiliary quantities like pressure or von Mises stress (Figure A.2, p.14, shows a pressure-field prediction example).

**All MLP details** (p.14, Appendix A.2.1): encoder/processor/decoder MLPs are ReLU, two hidden layers, layer+output size 128 (except δ^V whose output size matches the prediction), LayerNorm on all outputs except δ^V. All inputs/targets normalized to zero mean/unit variance from dataset statistics. Trained on a single V100 GPU, Adam, 10M training steps, exponential LR decay 1e-4 → 1e-6 over 5M steps.

**Adaptive remeshing** (p.5, Section 3.2). A **sizing field** tensor S(u) ∈ R^{2×2} at each node specifies the maximum allowed (possibly anisotropic/direction-dependent) edge length: an edge u_ij is valid iff u_ij^T S_i u_ij ≤ 1; otherwise it must be split. Given S, a generic local remesher R can split invalid edges (refine) and collapse edges where doing so creates no new invalid edges (coarsen): M' = R(M, S). Rather than calling a domain-specific remesher at every rollout step (which would defeat the point of a learned model), MGN **learns the sizing field itself** with the same encode-process-decode architecture (an extra decoder head outputs the sizing tensor per node), and at test time predicts both the next state and the sizing field, then hands both to a generic domain-independent remesher: M^{t+1} = R(M̂^{t+1}, Ŝ^{t+1}). Demonstrated on triangular meshes (Appendix A.3, p.15–16, describes the local remesher's three primitive operations — edge split, edge collapse, edge flip governed by an anisotropic Delaunay criterion — implemented as: split all invalid edges in descending order of the sizing metric, flip, collapse all collapsible edges in ascending order, flip again).

If ground-truth sizing-field labels aren't available from the simulator, MGN can **estimate them** from a sequence of meshes (Appendix A.3.1, p.16): solve for the sizing tensor S_i that is the (near-optimal) minimum-area, zero-centered ellipse containing the points u_ij, via the MINIDISK algorithm (Welzl 1991).

**Noise injection for rollout stability** (p.5, Section 3.3; details in Appendix A.2.2, p.14–15). Trained purely with one-step L2 supervision (predicted p_i vs ground truth p̄_i; sizing field similarly supervised with L2). To make the model robust to being unrolled for hundreds/thousands of steps at test time (where its own prediction errors compound), the paper adopts the same training-noise strategy as its precursor, GNS (Sanchez-Gonzalez et al. 2020): add random normal noise (zero mean, tuned fixed variance) to the most recent value of the corresponding dynamical variable during training, and **correct the targets accordingly** so the decoder still learns to remove the added perturbation. Noise scale was tuned per dataset around the natural one-step model error, scanning on a log scale (two values per decade) — table of noise scales given in Appendix A.2.3 (p.15), e.g. FlagSimple pos: 1e-3, FlagDynamic pos: 3e-3, CylinderFlow momentum: 2e-2, Airfoil momentum: 1e1 / density: 1e-2. For first-order systems the correction is a direct target adjustment. For second-order (cloth) systems the correction is ill-posed (correcting position noise perfectly for both next-step position and next-step velocity is impossible simultaneously) and the paper treats the split as a hyperparameter γ ∈[0,1] weighting a position-consistent vs. velocity-consistent target acceleration; best empirical performance was γ = 0.1 (p.15). With h>1 history steps, noise is added as a random walk so the *last* step's variance matches the target noise variance, matching GNS's approach.

**Kinematic / scripted nodes.** A one-hot node-type vector lets the model distinguish normal (simulated) nodes from kinematic nodes that are either fixed (e.g., the two nodes pinning a flag) or follow scripted motion (e.g., the actuator in DeformingPlate); for scripted nodes the model is additionally given the next-step world-space velocity as an extra input so its predictions stay consistent with the actuator's motion (Appendix A.1, p.14).

**Generalization tests** (p.8, Section 5 "Generalization"):
- **Parameter generalization (Airfoil)**: trained on angle of attack −25°…25° and Mach 0.2–0.7; tested at steeper angles (−35°…35°) and higher inflow speeds (Mach 0.7–0.9). Rollout RMSE rises only slightly: from 11.5 (training) to 12.4 (steeper angles) and 13.1 (higher inflow speed).
- **Wind-speed/direction generalization (FlagDynamic variant)**: trained with wind speed/direction varying between trajectories (constant within each trajectory); at test time wind can be varied freely, extrapolating outside the trained parameter ranges. Wind-speed vector appended as a node feature (Appendix A.1, p.14).
- **Shape generalization**: model trained on simple rectangular cloth generalized to three disconnected fish-shaped flags — both dynamics model and learned remesher transferred, predicted dynamics visually similar to ground truth.
- **Extreme shape+scale generalization ("WindSock")**: same rectangular-cloth model tested on a windsock with tassels — never saw a non-flat starting state during training, and the windsock mesh averages **20k nodes, an order of magnitude more than training** (Figure 4b, p.6). Demonstrates the central claim: because the model learns resolution/scale-independent local physics, one can train cheaply on small systems and deploy on much larger ones untrainable directly.
- **Detailed scaling analysis (Appendix A.5.3, p.18, Figure A.3)**: model trained on regular-sized FlagDynamic run on scaled-up/down FlagDynamic variants plus WindSock and FishFlag. 50-step rollout RMSE shows **no systematic trend with node count** — performance is roughly scale-invariant; error on new shapes (WindSock, FishFlag) is only slightly higher than in-distribution. Full-trajectory RMSE *does* correlate more with system size, but the paper attributes this to decoherence (chaotic divergence after ~50 steps) scaling geometrically with object size (e.g. an angular perturbation at a flag's fixed base produces bigger positional error at the tip of a larger flag) rather than a genuine loss of physical accuracy.
- **Resolution-independent learning**: since irregular/dynamically-changing meshes are used throughout training, the network is explicitly pushed toward learning physics that doesn't depend on local mesh density.

### 1.4 Comparisons to baselines (Section 5, p.6–9; Figure 5, p.7)

- **Learned remeshing vs. ground-truth mesh sequence** (FlagDynamic, SphereDynamic): dynamics+sizing models trained together, compared against running the forward dynamics model on the *true* mesh sequence. All learned-remeshing variants (labeled sizing data vs. estimated sizing targets) produce visually plausible dynamics and are "on par" quantitatively (Figure 5c) — footnote notes the ground-truth comparison needs interpolation onto the GT mesh, incurring a small penalty for the learned-remeshing variants.
- **GNS (mesh-free particle baseline, Sanchez-Gonzalez et al. 2020)** on the fixed-mesh FlagSimple dataset: GNS uses fixed-radius connectivity (10–20 neighbors/node) with relative world-space position edges, no notion of the cloth's rest state. Error accumulates dramatically and rollouts destabilize (small improvement with 5 steps of history vs. 1). A hybrid **GNS+mesh-pos** (adding a mesh-space relative-position edge feature to GNS) gets rollout error on par with MGN on FlagSimple, but develops entangled-triangle artifacts (no reliable surface understanding), and on irregularly spaced meshes it fails to produce stable rollouts at all — fixed-radius connectivity oversamples dense mesh regions and undersamples sparse ones. **Conclusion drawn**: both mesh-space positional information *and* message passing along mesh edges are necessary for irregular meshes (p.8).
- **Ablation: no world edges** — on FlagDynamic and SphereDynamic, removing world-space edges (mesh-space-only message passing) increases rollout RMSE by **51%** and **92%** respectively; for SphereDynamic the obstacle mesh and cloth mesh aren't even connected without world edges, so their interaction can't be computed at all — this is the sharpest illustration of why world edges exist.
- **GCN baseline** (Kipf & Welling architecture, replicating Belbute-Peres et al. 2020's differentiable-solver-plus-GCN pipeline without the solver-in-the-loop / super-resolution component): trained in the same framework (same noise, integration). On the paper's own steady-state task (AirfoilSteady, a reproduction of Belbute-Peres et al.'s setup with narrower angle range −10°…10°) the GCN's predictions were visually indistinguishable from ground truth, replicating that paper's results — but MGN's model (also adapted as a one-step direct predictor, conditioned on global Mach/angle-of-attack scalars) beat it: **RMSE ours 0.116 vs GCN 0.159** (p.16, Appendix A.4.2), despite the relative-encoding equivariance bias working *against* this global-field-prediction task. On the much richer full dynamical Airfoil task, GCN could not obtain stable rollouts at all, even when scaled up to a hybrid GCN-MLP variant (2-hidden-layer MLPs + LayerNorm, 15 GCN blocks instead of 6) — rollout quality remained poor.
- **Ablation: no relative encoding** (absolute positions as node features instead) — much worse, visual artifacts, rollout RMSE 26.5 on Airfoil (vs. FNO/GCN comparisons context on p.8–9), supporting the hypothesis that lack of relative encoding is what specifically hurts GCN.
- **Grid-based CNN (U-Net) baseline** (Thuerey et al. 2020 architecture, re-implemented to match the open-sourced code exactly): compared on the two Eulerian 2D domains by interpolating the region of interest onto a 128×128 grid. MGN outperforms U-Net on RMSE on both CylinderFlow and Airfoil (Figure 5a). On Airfoil the U-Net makes reasonable large-scale predictions but **undersamples the wake region around the wingtip even while using 4× more cells** to cover a region 16× smaller than MGN's mesh (Figure A.1, p.13, shows Airfoil spans a large domain with 5k nodes while resolving sub-millimeter detail at the wingtip). Similar undersampling seen around the CylinderFlow obstacle. U-Net also develops fluctuations during rollout. Conclusion: mesh-based prediction has advantages even in flat 2D domains where grids are a natural fit.

### 1.5 Key hyperparameter findings (p.9, Figure 5d)

- **Number of message-passing steps L**: increasing L generally improves performance but costs more compute; L=15 found to be a good efficiency/accuracy tradeoff across all systems tested.
- **History length h**: shortest possible history performs best (h=1 for cloth just to estimate velocity, h=0 otherwise); more history causes overfitting. This is explicitly called out as differing from GNS, which needed h ∈ {2,…,5} for best performance — a genuine architectural difference attributable to the mesh-space positional information making extra history redundant/harmful.
- Model is described as fairly insensitive to many other architecture choices (latent width, number/size of MLP layers).

### 1.6 Error-metric methodology (Appendix A.5.2, p.17)

Rollout RMSE = RMSE of position (Lagrangian) or momentum (Eulerian), averaged over all spatial coordinates, all mesh nodes, all rollout steps in the trajectory, and all 100 test trajectories; error bars in Table 1 / Figure 5(a–c) are standard error across the 100 trajectories; Figure 5(d) error bars are min/median/max over 3 seeds. For FlagSimple/FlagDynamic, decoherence sets in after ~50 steps due to cloth's chaotic dynamics, so the paper reports rollout-50 (first 50 steps) as the more discriminating metric — though it notes the qualitative conclusions hold either way. Airfoil RMSE is computed within a region of interest around the wing (Figure A.1 middle), matching the region shown in figures/videos; grid-based baseline predictions are mapped back onto the ground-truth mesh before computing error, to keep the comparison fair.

### 1.7 Stated limitations and future work (Section 6 "Conclusion", p.9)

- The paper frames MGN as general-purpose but notes several concrete extensions as future work rather than solved problems: (1) domain-specific variants with **physics-based auxiliary loss terms** or **energy-conserving integration schemes** could improve accuracy further; (2) the adaptive-meshing approach here *learns to imitate a ground-truth remesher's sizing field* rather than learning a discretization that directly optimizes prediction accuracy or downstream task performance — proposed as an open direction; (3) being differentiable, MGN "may be useful for design optimization or optimal control tasks" — framed as a promise, not a demonstrated capability in this paper.
- Practical limitations visible in the results themselves (not explicitly flagged as "limitations" in the text but evident from the data): Airfoil rollout error is by far the largest of any dataset (RMSE rollout-all 11529×10⁻³ vs. single-digit-to-tens ×10⁻³ for the other domains) — compressible aerodynamics with its huge mesh-resolution dynamic range (2×10⁻⁴ m to 3.5 m edges) is clearly the hardest case in the suite. FlagDynamic's t_full (837 ms/step GPU) is far above t_model (43 ms/step) because remeshing + graph recomputation dominate cost there — the "fast NN, slow remesh/graph rebuild" tradeoff is visible directly in Table 1, and this is echoed by CFL-type stability-independence claims elsewhere in the PDEBench paper (Part 2) about ML models generally.
- No comparison to physics-informed neural network baselines or Fourier neural operators is included in this paper (FNO postdates the initial version but MGN doesn't compare to it) — the natural bridge to PDEBench (Part 2), which does include FNO.

### 1.8 Teachable moments (MGN)

- **Two coordinate spaces, one graph.** The mesh-space/world-space split is the single most important conceptual device in the paper: mesh edges → "what is this node connected to as part of the object's geometry" (internal PDE-like dynamics); world edges → "what is spatially near this node right now regardless of mesh topology" (contact/collision). Students should be able to explain *why* SphereDynamic breaks completely without world edges (obstacle and cloth aren't mesh-connected at all).
- **Relative/equivariant encoding as the mechanism for generalization**, not just a stylistic choice — directly demonstrated by the "no relative encoding" ablation (RMSE 26.5 vs. much lower with it) and by the GCN's failure being attributed to the *combination* of absolute positions plus no edge-level message computation.
- **Encode-Process-Decode + explicit numerical integration** is a template worth teaching generally: the network predicts a *derivative* (acceleration, velocity, rate of change), and a classical Euler integrator (not a learned component) turns that into a next state. This separates "what physics looks like locally" (learned) from "how to step time forward" (fixed, simple), and it is the same pattern used in many later neural PDE solvers.
- **A common misconception this paper corrects**: that more history steps always help sequence models. Here more history *causes overfitting*; the right amount is domain-dependent and can be surprisingly small (h=0 or 1). This directly contradicts GNS's finding, and the paper explains why (mesh-space information already gives the network what history was providing indirectly for GNS).
- **Adaptive remeshing without a remesher in the loop.** Key idea: you don't need to call the actual (often slow, hand-tuned) remeshing algorithm at inference time — you only need to imitate its *decision of where more resolution is needed* (the sizing field), and hand that decision to a cheap generic remesher. This "learn the policy, keep the mechanism simple" pattern generalizes well beyond meshing.
- **Noise injection for closed-loop stability** is the standard trick (borrowed from GNS) for bridging the train/test mismatch of "trained on one-step supervision, tested via long autoregressive rollout" — a recurring theme also visible in PDEBench's discussion of U-Net's autoregressive instabilities (Part 2, Section 2.4) and the "pushforward trick." Comparing how MGN's noise-injection and PDEBench's pushforward trick both attack the same underlying problem (compounding rollout error) from different angles is a good cross-paper teaching link.
- Quote (p.9): *"MESHGRAPHNETS are a general-purpose mesh-based method which can accurately and efficiently model a wide range of physical systems, generalizes well, and can be scaled up at inference time."*
- Quote (p.8, on generalization): *"the architectural choice of using relative encoding on graphs has shown to be very conducive to generalization."*

## PART 2 — PDEBench

### 2.1 Plain-language summary

PDEBench is a large, standardized benchmark suite built to give the "scientific machine learning" community something ImageNet-like: a common set of ready-to-download datasets, a shared data format, baseline models already trained and scored, and — crucially — a richer set of evaluation metrics than the field had been using. It covers 11 distinct partial differential equations (from simple 1D advection up to 3D compressible turbulence), spanning both easy textbook problems and harder, more realistic ones with awkward boundary conditions, shocks, and turbulence. For each PDE the authors generated large datasets (thousands to tens of thousands of simulated trajectories) using classical numerical solvers, then trained three well-known machine-learning surrogate models — a U-Net (image-style convolutional network), a Fourier Neural Operator (FNO), and Physics-Informed Neural Networks (PINNs) — and measured how well each one reproduces the true physics, not just in a raw root-mean-squared-error sense but also on whether it preserves conserved quantities, gets boundaries right, and gets each spatial frequency band right. The headline finding is that FNO is generally the strongest of the three, but that none of the methods is a free lunch: FNO's accuracy collapses in genuinely turbulent, high-Reynolds-number, near-shock regimes because its own architecture caps how fine a spatial detail it can represent, U-Net has serious stability problems when run open-loop for many time steps unless trained with tricks that fight that instability, and PINNs cannot even be applied to some of the tasks (like Darcy flow) at all. PDEBench also introduces one of the few standardized inverse-problem benchmarks in this space (estimating the unknown initial condition of a PDE from its later state) and documents, with exact numbers, exactly where each method's error is concentrated (which frequency band, boundary vs. interior, and so on) — turning the benchmark itself into a map of open problems for the field. (p.1, abstract; p.2–3, Section 1)

### 2.2 Formal problem definition and key definitions (p.3–4, Section 3.1)

A PDE solution is a vector-valued function v : T × S × Θ → ℝ^d over spatial domain S, temporal index T, and parameter space Θ (which may include spatially-varying, function-valued parameters, e.g. a spatially heterogeneous conductivity field). The **forward propagator** F_θ maps the solution at one time step to the next: F_θ : v_θ(t,·) → v_θ(t+1,·). In practice the *discretized* forward propagator uses ℓ ≥ 1 consecutive past time steps: 
F̊_θ : v_θ(t−ℓ,·),…,v_θ(t−1,·) ↦ v_θ(t,·). 
Scientific ML seeks an emulator F̂_θ ≈ F̊_θ, fit by minimizing a loss functional L summed over all timesteps and all training samples k ∈ dataset D:
b̂φ = argmin_φ Σ_t Σ_k L(F_{θ_k,φ}{v^(k)_{θ_k}([t−ℓ:t−1],·)}, v^(k)_{θ_k}(t,·))  (Eq. 1, p.4).
D is generated by a ground-truth solver; both initial conditions and PDE parameters θ can be varied across samples.

**Inverse problems** (p.4, following the same section): given later observed states v_θ([t:t+ℓ],·), estimate an unknown initial condition v_θ(0,·) or unknown parameter θ. PDEBench follows a surrogate-based approach (as in prior work by two of the same authors) — the forward surrogate is used as a mean predictor under an assumed mean-zero observation noise model, and a prior over the unknown is assumed. (p.4 notes GANs or VAEs are alternative inversion methods not used here.)

### 2.4 PDE definitions given in detail (Appendix D, p.18–22)

- **1D Advection** (D.1, p.18): ∂_t u + β ∂_x u = 0, x∈(0,1), t∈(0,2]; exact solution u(t,x)=u_0(x−βt); periodic BC only; initial condition is a superposition of sinusoids u_0(x)=Σ A_i sin(k_i x + φ_i) with k_i=2π{n_i}/L_x, n_i random integers in [1,n_max]=[1,8], N=2 waves, A_i~U(0,1), φ_i~U(0,2π); occasionally an absolute-value and/or window-function operation applied with 10% probability each. Solved with 2nd-order upwind finite differences.
- **1D Diffusion-Reaction** (D.2, p.19): ∂_t u − ν ∂_xx u − ρu(1−u) = 0, x∈(0,1), t∈(0,1]; exponential-rate growth from the source term is explicitly called out as testing the ability to capture rapid dynamics; periodic BC, same sinusoidal-superposition IC (normalized by max value to avoid ill-posed IC). Solved with 2nd-order central differences for diffusion, piecewise-exact-solution (PES) method for the reaction term.
- **Burgers' equation** (D.3, p.19): ∂_t u + ∂_x(u²/2) = (ν/π) ∂_xx u, x∈(0,1), t∈(0,2]; defines an effective Reynolds number R ≡ πuL/ν — R>1 gives strong nonlinear/shock-forming behavior, R<1 is diffusive. Same periodic/sinusoidal-IC setup. Solved with 2nd-order upwind (advection term) + central difference (diffusion term).
- **Darcy Flow** (D.4, p.20): steady-state −∇·(a(x)∇u(x)) = f(x) on unit square, u=0 on boundary; the diffusivity field a(x) is the *input*, force term f set to a constant β controlling the solution's scale. Obtained numerically by solving the corresponding *time-dependent* equation ∂_t u − ∇·(a∇u) = f from a random-field IC until steady state, using the same solver style as 1D diffusion-reaction.
- **Compressible Navier–Stokes** (D.5, p.20–21; also stated at Eq. 2, p.5 of main text): 
  ∂_t ρ + ∇·(ρv) = 0; 
  ρ(∂_t v + v·∇v) = −∇p + η∇²v + (ζ+η/3)∇(∇·v); 
  ∂_t(ε+ρv²/2) + ∇·[(ε+p+ρv²/2)v − v·σ'] = 0, 
  with ε = p/(Γ−1), Γ=5/3 the internal energy, σ' the viscous stress tensor, η/ζ shear/bulk viscosity. **15 distinct configurations are generated**, varying N_d (1D/2D/3D), initial-field type (random field vs. turbulence vs. shock-tube), boundary condition (periodic vs. outgoing), and (η,ζ,M): e.g. 1D random-field periodic at (η,ζ)=(1e-8,1e-8), (1e-2,1e-2), (1e-1,1e-1); 1D random-field outgoing; 1D shock-tube outgoing; six 2D random-field periodic combos crossing (η,ζ)∈{1e-8,1e-2,1e-1}²-ish with M∈{0.1,1.0}; 2D turbulence-IC periodic at M∈{0.1,1.0}; 3D random-field periodic at (η,ζ,M)=(1e-8,1e-8,1.0) and (1e-2,1e-2,1.0). "Outgoing" BC copies neighbor-cell values to the boundary, letting waves/fluid exit the domain (standard for astrohydrodynamics). Random-field IC uses the same sinusoidal-superposition construction extended to 2D/3D, with density/pressure built from a uniform background plus the perturbation field. Turbulence IC constructs a divergence-free-ish velocity field via Helmholtz decomposition in Fourier space (n=4 modes, amplitude tied to a target Mach number via v̄=c_s M). **Shock-tube ("Riemann problem") IC**: Q(x,0)=(Q_L,Q_R) with Q=(ρ,v,p), Q_L/Q_R and the discontinuity location randomly chosen — explicitly framed as "a rigorous test if ML models fully understand" the compressible NS equations, since shocks/rarefactions are hard to get right without actually solving the PDE. Solved with 2nd-order HLLC scheme + MUSCL method (inviscid part), central differences (viscous part).
- **Incompressible Navier–Stokes** (D.6, p.21–22): ∇·v=0, ρ(∂_t v+v·∇v) = −∇p + η∇²v, augmented with an external vector forcing term u: ρ(∂_t v + v·∇v) = −∇p + η∇²v + u (Eq. 19). Non-periodic (Dirichlet, velocity clamped to zero at the boundary) — deliberately included to challenge FNO-style methods that assume periodicity. IC v_0 and forcing u drawn from isotropic Gaussian random fields with truncated power-law spectral decay (τ_{v0}=−3, σ_{v0}=0.15; τ_u=−1, σ_u=0.4); domain is the unit square, ν=0.01; simulated with Phiflow.
- **2D Shallow-Water equations** (D.7, p.22; also Eq. 3, p.5 of main text): ∂_t h + ∇·(hu) = 0; ∂_t(hu) + ∇(u²h + ½g_r h²) = −g_r h∇b (and analogously for hv), with h=water depth, u,v=horizontal/vertical velocity, b=bathymetry, g_r=gravity. Mass/momentum conservation hold even across shocks (explicitly noted as making this a genuinely challenging benchmark, applicable to tsunami/flood modeling). Benchmark scenario: 2D radial dam break on Ω=[−2.5,2.5]², initial water height a circular bump of height 2.0 inside radius r (r~U(0.3,0.7)), height 1.0 outside; solved with PyClaw's finite-volume solver.
- **Diffusion-Sorption** (D.8, p.22–23): ∂_t u = (D/R(u)) ∂_xx u, x∈(0,1), t∈(0,500]; retardation factor R(u) follows the Freundlich sorption isotherm: R(u) = 1 + ((1−φ)/φ) ρ_s k n_f u^{n_f−1}, with φ=0.29 (porosity), ρ_s=2880 (bulk density), k=3.5×10⁻⁴ (Freundlich parameter), n_f=0.874 (Freundlich exponent), D=5×10⁻⁴ (effective diffusion coefficient). IC u(0,x)~U(0,0.2). Boundary conditions are **non-trivial and explicitly called out as hard for convolutional architectures**: u(t,0)=1.0 (Dirichlet) and u(t,1)=D∂_x u(t,1) (a genuine **Cauchy/derivative** condition, not a simple padded constant). Real-world motivation: groundwater contaminant transport. Also noted: R(u) is singular at u=0, making the diffusion coefficient itself nonlinear in u. Solved via finite-volume spatial discretization + 4th-order Runge-Kutta (scipy) time integration; provided at N_x=1024, N_t=501 (plus a temporally downsampled N_t=101 version).
- **2D Diffusion-Reaction (Fitzhugh–Nagumo)** (D.9, p.23–24): two nonlinearly coupled fields, activator u and inhibitor v: ∂_t u = D_u∇²u + R_u(u,v), ∂_t v = D_v∇²v + R_v(u,v), domain x,y∈(−1,1), t∈(0,5]. Reaction terms from the Fitzhugh-Nagumo equations: R_u = u − u³ − k − v, R_v = u − v, with k=5×10⁻³, D_u=1×10⁻³, D_v=5×10⁻³. IC is standard normal noise u,v(0,x,y)~N(0,1). No-flow **Neumann** BC on all four fields' gradients. Real-world motivation: biological pattern formation (Turing patterns). Provided at N_x=N_y=512, N_t=501 (plus downsampled 128×128×101 version). Same FVM + RK4 solver as diffusion-sorption.
- **Gradient-Based Inverse Method** (D.10, p.24): minimizes L(u(T,x|u_0), u(T,x|û_0)) where û_0 ~ p_θ(u_0 | u(T,x)) is a deterministic generation process parameterized by bilinear interpolation (θ = interpolation control points recovering the initial condition). Figure 12 (p.24) shows the 1D advection (β=0.1) inverse solution: predicted vs. true IC, predicted vs. true forward value at t=T, and the power spectral density showing error concentrated in mid-to-high frequencies.

### 2.5 Metrics — full definitions (Section 3.3, p.5–6; detailed in Appendix B, p.17)

Two "views," Data and Physics:

| Scope | Acronym | Metric | What it captures |
|---|---|---|---|
| Data | RMSE | root-mean-squared error | standard global error |
| Data | nRMSE | normalized RMSE | scale-independent global error |
| Data | max error | maximum local error | worst case / stability proxy |
| Physics | cRMSE | RMSE of a conserved value | whether a physically conserved quantity is respected |
| Physics | bRMSE | RMSE at the boundary | whether the boundary condition was learned |
| Physics | fRMSE (low/mid/high) | RMSE in Fourier space, by frequency band | wavelength-dependent accuracy |

Exact formulas (Appendix B, p.17, Eq. 4–5):
- **nRMSE** ≡ ‖u_pred − u_true‖₂ / ‖u_true‖₂.
- **max error** — the worst single prediction error; explicitly framed as both a local-performance measure and a proxy for the time-stepping's numerical stability.
- **cRMSE** ≡ nRMSE-style but on the summed/conserved quantity: ‖Σu_pred − Σu_true‖₂ / N.
- **bRMSE** — error restricted to boundary points, testing whether the boundary condition specifically has been learned.
- **fRMSE** = sqrt[ Σ_{k=kmin}^{kmax} |F(u_pred) − F(u_true)|² / (kmax − kmin + 1) ], where F is the discrete Fourier transform. Frequency bands used throughout the paper: **Low: k_min=0, k_max=4; Middle: k_min=5, k_max=12; High: k_min=13, k_max=∞.** For multi-dimensional cases, the angular Fourier coordinate is first integrated out, then summed along the radial k-coordinate.

**Inverse-problem metrics** (Appendix B.1, p.17–18): two separate quantities are measured — (a) error in the estimated initial condition itself, L(u_0, û_0); (b) error in the forward prediction produced from that estimated IC, L(u(t,x|u_0), u(t,x|û_0)) — the paper notes error (b) is typically smaller because high frequencies in the true error decay quickly under the forward PDE. Metrics used: MSE, normalized ℓ2 norm (nL2), normalized ℓ3 norm (nL3), plus FFT versions of each (fMSE, fL2, fL3), each split into low (0–¼ of max frequency), middle (¼–¾), and high (¾–max) frequency bands. Evaluated at fixed horizon T=15 for all datasets except the CFD dataset, evaluated at T=5 (p.18/C.1, p.18).

### 2.6 Baseline models (Section 3.4, p.6)

- **U-Net** (Ronneberger et al. 2015) — an auto-encoding convolutional architecture with multi-resolution skip connections; treated here as a black-box general-purpose regressor. The paper's own implementation **extends the original 2D U-Net to 1D and 3D** to cover all the benchmark's spatial dimensions.
- **FNO — Fourier Neural Operator** (Li et al. 2021) — a Neural Operator that learns a resolution-invariant map by operating in Fourier space; framed as the strongest baseline overall.
- **PINNs — Physics-Informed Neural Networks** (Raissi et al. 2019, implemented via the open-source DeepXDE library) — approximate the PDE solution directly with a network u_θ(t,x), trained via a multi-objective loss combining PDE-residual minimization with boundary/initial-condition matching. Key structural limitation stated explicitly: **PINNs must be retrained for every new initial/boundary condition** — they are not amortized emulators the way U-Net/FNO are, which is why the paper trains and averages over 10 separate samples per dataset to get error bars (Appendix C, p.18) rather than using one trained model across the whole test set.
- **Gradient-Based Inverse Method** — since the forward surrogate is differentiable, the inverse problem is solved by gradient descent on the prediction loss, with the unknown initial condition parameterized via bilinear interpolation (citing MacKinlay et al. 2021, a benchmark co-author's own prior work).

### 2.7 Training protocol and hyperparameters (Section 4.1, p.7; Appendix C, p.18)

- 90% train / 10% test split throughout.
- **FNO**: trained following the original FNO paper's implementation/hyperparameters/protocol; 500 epochs, Adam, initial LR 1e-3, halved every 100 epochs.
- **U-Net**: trained similarly to FNO but **autoregressively with the "pushforward trick"** (with slight modification relative to the cited original implementation) — this detail becomes central in Section 4.3 (below).
- **PINN**: DeepXDE implementation, 15,000 epochs, Adam, LR 1e-3, a fully-connected network of depth 6 with 40 neurons/layer (matching DeepXDE's own example configs); trained/averaged over 10 different samples per dataset for reliable error bars (since a single PINN model is only valid for one specific IC/BC).
- **Inverse-problem training** (Appendix C.1, p.18): reduced to 20 epochs; final time step T=15 for all datasets except CFD (T=5); 64 hidden values estimated for the IC, 100 test samples, learning rate 0.2 for the gradient method, MSE loss.
- **Hardware**: GeForce RTX 2080 (1D/2D), GeForce GTX 3090 (3D) for the main training runs (p.7); a separate, explicitly documented runtime-comparison hardware config used for Section 4.4/Appendix F/G: 2×AMD EPYC 7742 CPU + 1×NVIDIA Volta V100 GPU, PyTorch 1.11/CUDA 11.3 (Table 14, p.21) for 2D scenarios; 1×NVIDIA GeForce RTX 3090, PyTorch 1.11/JAX 0.2.26 with CUDA 11.3 (Table 16, p.21) for the 3D-CFD runtime comparison (resolution there reduced to 64³ due to memory, even though the official dataset ships at 128³).

### 2.8 Baseline results (Section 4.2, p.7–9, Figure 2/3; full detail in Appendix E Tables 5–13, p.28–35)

**Headline (Figure 2, p.7; Section 4.2 text, p.8)**: FNO is the best baseline on most metrics, including the *physics-aware* ones (conserved quantities, boundaries) — it "learns the differential operators well." FNO shows a remarkably **flat ~4×10⁻⁴ error across the whole frequency spectrum** for many problems, evidence it is genuinely learning in Fourier space rather than only matching low frequencies. PINNs perform "better than expected" with high-frequency features "despite prior observations" (citing Wang, Yu & Perdikaris 2022 on why PINNs typically struggle to train) — a genuine, explicitly flagged surprise result. For the **inverse problem** (Figure 2b, 4 of the 11 1D datasets tested), FNO again outperforms U-Net.

**Important omissions/exclusions in the baseline comparison** (footnotes 6, p.8): PINN was *not run at all* on the 2D/3D compressible Navier–Stokes datasets (limited GPU memory) and *not run at all* on Darcy Flow (the Darcy setup maps diffusivity field a(x) → steady-state solution, a mapping DeepXDE's PINN formulation cannot represent). This is a genuine capability gap, not a performance number — worth flagging explicitly as a place PINNs categorically fail to apply.

**Three documented failure modes** (Section 4.2, Figure 3, p.8):
1. **FNO vs. decreasing diffusion coefficient (Burgers')**: FNO's error rises sharply as the diffusion coefficient decreases and a strong discontinuity (shock) appears — attributed to **Gibbs phenomenon** arising from FNO's limited maximum representable wave frequency in Fourier space; **fRMSE-high rises by two orders of magnitude** in this regime.
2. **Normalized RMSE vs. decreasing force term (Darcy Flow)**: nRMSE increases as the force term decreases (equivalently, as the solution's overall scale shrinks — force term 0.01 corresponds to mean(|u|)≈0.01). Interestingly, **U-Net is consistently better than FNO here**, which the authors attribute to the task's strong resemblance to the plain image-denoising/regression task U-Net was originally designed for.
3. **Compressible Navier–Stokes overall**: RMSE is "very bad" compared to basic PDEs like Burgers. Counter-intuitively, the **3D inviscid case shows lower error than the 2D inviscid case** — attributed to the 3D dataset's lower spatial resolution producing smoother train/validation samples that FNO can fit efficiently; the paper explicitly flags this as evidence that **high-resolution training data is needed for real-world problems at Reynolds numbers above 10⁶.**

**Selected exact numbers from the detailed appendix tables** (Tables 5–13, p.28–35 — U-Net / FNO / PINN unless noted):
- Diffusion-sorption: RMSE 5.8×10⁻² (U-Net) / 5.9×10⁻⁴ (FNO) / 9.9×10⁻² (PINN) — FNO roughly 100× better than U-Net and ~170× better than PINN here (Table 5, p.28).
- 2D diffusion-reaction: RMSE 6.1×10⁻² (U-Net) / 8.1×10⁻³ (FNO) / 1.9×10⁻¹ (PINN); nRMSE 8.4×10⁻¹ / 1.2×10⁻¹ / 1.6×10⁰ (Table 5).
- Shallow-water: RMSE 8.6×10⁻² (U-Net) / 4.5×10⁻³ (FNO) / 1.7×10⁻² (PINN) — PINN actually beats U-Net here on some metrics (max error 1.3×10⁻³ for PINN vs 4.4×10⁻¹ for U-Net) (Table 5).
- Advection, β sweep (Table 6, p.29): at β=0.1, RMSE = 3.1×10⁻² (U-Net) / 4.1×10⁻³ (FNO) / 6.7×10⁻³ (PINN); at β=4.0, PINN's RMSE jumps to 6.6×10⁻¹ (its worst result in the sweep) while FNO stays around 3.9×10⁻³ — PINN clearly degrades faster than FNO/U-Net as advection speed increases.
- Burgers', ν sweep (Table 7, p.30): at ν=0.001 (strong shocks), RMSE = 1.3×10⁻¹ (U-Net) / 9.6×10⁻³ (FNO) / 2.2×10⁻¹ (PINN); at ν=1.0 (diffusive, smooth), RMSE drops to 2.7×10⁻² / 1.2×10⁻³ / 1.1×10⁻² respectively — all three methods do better as the problem becomes smoother/less shock-like, consistent with the Gibbs-phenomenon explanation above.
- Darcy Flow, β sweep (Table 8, p.31): U-Net beats FNO at every tested β (0.01, 0.1, 1.0, 10.0, 100.0) — e.g. at β=1.0, RMSE 6.4×10⁻³ (U-Net) vs 1.2×10⁻² (FNO); nRMSE actually *decreases* with increasing β (from 1.1 at β=0.01 down to ~4×10⁻³ at β=100), consistent with the "smaller force term ⇒ smaller solution scale ⇒ worse normalized error" story in the main text.
- 1D diffusion-reaction, ν/ρ sweep (Table 9, p.32): at high ρ (ρ=10.0), U-Net and FNO both achieve near-zero error (~1e-8, essentially solving the problem exactly) while PINN's error stays around 1.4×10⁻²–3.2×10⁻² — a case where the "easy" parameter regime is *trivial* for the neural surrogates but PINN still shows non-negligible residual error.
- 1D compressible NS (Table 10, p.33): the **inviscid random-periodic case is dramatically harder than the viscous cases** — U-Net RMSE 1.7×10¹ (inviscid) vs. 9.9×10⁻¹ (η=ζ=0.01) vs. 6.6×10⁻¹ (η=ζ=0.1); FNO similarly worse on inviscid (4.7×10⁻¹) than viscous (2.7×10⁻¹ at η=ζ=0.01, 9.3×10⁻² at η=ζ=0.1) — viscosity smooths the solution and makes it easier to learn, the opposite of the runtime story (below) where viscosity makes the *classical solver* slower.
- 2D/3D compressible NS (Tables 11–13, p.34–35): U-Net is dramatically worse than FNO in the low-Mach, low-viscosity regimes (e.g. 2D, M=0.1, η=ζ=0.1: RMSE 4.7×10⁻² U-Net vs 4.9×10⁻³ FNO — roughly 10×) but the two converge and are nearly tied in the **turbulence-IC** cases (2D M=0.1 turbulence: 3.3×10⁻¹ vs 2.8×10⁻¹; 3D M=1.0 turbulence: 8.1×10⁻² vs 8.2×10⁻²) — turbulence appears to erase FNO's usual advantage.

**Temporal error analysis — U-Net autoregressive instability (Section 4.3, p.9; Figure 5, p.9)**: training U-Net in fully autoregressive/open-loop mode (feeding back its own 1-step-ahead prediction with no correction) causes error to blow up rapidly with more unrolled steps. Three U-Net training strategies were compared (1-step-only, plain autoregressive/AR, and AR with the **pushforward trick**, "PF-20"): **pushforward training gives the best stability for all problems and the best accuracy over longer prediction horizons**, which is why it was adopted as the paper's standard U-Net baseline throughout.

**Temporal extrapolation (Section 4.3, p.9, Figure 5c)**: FNO trained on only *half* the available time steps for 1D Advection and 1D Burgers, then evaluated beyond the trained horizon. Error **increases monotonically for t beyond the training window**, and the paper concludes plainly: *"present ML models cannot properly capture the dynamic behavior of the PDEs, and it is a challenging task to provide reliable predictions beyond the time experienced during training"* (p.9) — i.e., these surrogates are good interpolators in time but not reliable extrapolators.

### 2.9 Inverse problem — detailed error tables (Appendix B.1/C.1/Section 4.2b; Tables 2–4, p.25–27)

Four of the eleven 1D datasets tested (Advection β=4, Burgers ν=1, CFD_Shock_Trans, ReacDiff ν=1/ρ=2), comparing FNO vs. U-Net:
- MSE of the estimated initial condition (Table 2, p.25): FNO consistently far better than U-Net, e.g. Advection_beta4 MSE 2.4×10⁻³ (FNO) vs. 1.0×10⁰ (U-Net) — roughly 400× better; CFD_Shock_Trans MSE 3.4×10⁰ (FNO) vs. 1.1×10² (U-Net).
- MSE'/nL2'/nL3' (the "prime" metrics, i.e. error of the *forward prediction from the estimated IC* rather than the IC itself) are consistently smaller than the unprimed values for both models across all four datasets — confirming the paper's stated expectation (Appendix B.1) that IC-estimation error is larger than downstream forward-prediction error, because high spatial frequencies in the IC decay quickly under the forward PDE.
- Frequency-resolved inverse error (Tables 3–4, p.26–27) shows the largest inverse-problem error is consistently concentrated in the **middle frequency range** (visualized directly in Figure 12's power spectral density plot, p.24) — matching the qualitative claim in Section B.1 that "the largest error is found in the middle frequency range."

### 2.10 Inference-time / runtime comparisons (Section 4.4, p.9–10; Appendix F, p.21; Appendix G, p.21–22)

Main summary table (p.10):

| PDE | Resolution | Simulation time (s) | ML inference time (s) | ML training time (total, s) |
|---|---|---|---|---|
| Diffusion-sorption | 1024¹ | 59.83 | 0.32 | 48,760 |
| 2D CFD (η=ζ=0.1) | 512² | 582.61 | 0.14 | 107,567 |
| 3D CFD (inviscid) | 64³ | 60.06 | 0.14 | 12,387 |

Detailed per-epoch breakdown (Appendix F, Tables 15/17, p.21): e.g. for diffusion-sorption at 1024¹, PDE solver per-sample time 59.83 s vs. FNO/U-Net inference 0.32 s each (≈187× faster once trained); PINN inference is even faster, 0.0027 s, but this is because the PINN evaluation is a single forward pass at fixed points, not an autoregressive rollout, and training epochs for PINN are far cheaper per-epoch (0.011 s/epoch × 15,000 epochs) than FNO/U-Net (~97 s/epoch × 500 epochs) — though total wall-clock PINN training is still substantial because DeepXDE trains one PINN per sample.

**Resolution scaling (Appendix G, Figure 13, p.22)**: across resolutions from 64 up to 1024 (2D) or 32–256 (3D), ML inference time is **nearly 3 orders of magnitude smaller** than the classical simulators at matched resolution, and — critically — **ML inference time is essentially independent of the diffusion coefficient/viscosity**, whereas the classical solver's cost *increases* with viscosity because of the CFL (Courant-Friedrichs-Lewy) stability condition: Δt ∝ Δx²/η for the explicit method used, versus Δt ∝ Δx for the inviscid case (a far milder restriction). The paper's stated conclusion: *"ML methods could even be suitable for solving for the problem with including strong-diffusive regime"* (p.22) precisely because they sidestep this CFL restriction that punishes classical explicit solvers in stiff/diffusive regimes.

**Error vs. resolution / discretization ("ground truth" sensitivity), Appendix H, Table 18, p.23**: 2D diffusion-reaction data generated at 512×512 and downsampled to 128×128 as "ground truth," compared against data generated *directly* at coarser (128×128) resolution — i.e. testing how much of the "error" against a coarse simulator is really just the coarse simulator's own discretization error rather than genuine ML model error. Result: **generating data at lower resolution already accumulates high discretization error relative to the baseline models' own prediction error** — e.g. RMSE of the raw low-res PDE solver itself (1.8×10⁻¹) is actually *larger* than FNO's prediction error (8.1×10⁻³) against the high-res ground truth, and comparable to U-Net's (6.1×10⁻²) and smaller than PINN's (1.9×10⁻¹). The paper explicitly flags that further sensitivity analysis across resolutions is needed to determine whether 512×512 is fine enough to be treated as ground truth at all — a genuine open methodological caveat about what "ground truth" even means in this benchmark.

### 2.11 Dataset access, format, size, and license (Section 3.5, p.6–7; Appendix K, p.44–50)

- **Format**: HDF5 files, one per PDE/IC-type/parameter combination. Arrays packed as (N, T, X, Y, Z, V): N=samples, T=time steps, X/Y/Z=spatial dims, V=field dimension. Not all dims present for every dataset (e.g. Darcy flow has no time dimension). Simulation parameters stored as HDF5 attribute strings in YAML, UTF-8 encoded (Appendix K.10, p.50). Filename convention: `${PDE name}--${Parameters}--{$Config}.h5`. Note (footnote 11, p.50): for compressible NS specifically, each variable (density, pressure, etc.) is stored as an *independent* array rather than stacked into a channel dimension, specifically to keep array sizes manageable and allow memory-efficient sub-sampled I/O.
- **Repository**: hosted on **DaRUS**, the University of Stuttgart's Dataverse-based FAIR-principles data repository, with a permanent DOI **doi:10.18419/darus-2986**. Accessible either by direct download from the DaRUS page or via the `pyDaRUS` Python package (three-line code example given, Listing 1, p.6). A separate PyTorch `FNODatasetSingle` data-loader class is provided for direct use with `torch.utils.data.DataLoader` (Listing 2, p.7). Configuration of both training and data generation is managed via the Hydra library.
- **Exact download/storage sizes** (Appendix K.9, p.50, explicit numbers): **1D data: 4–20 GB per dataset file; 2D data: 6–100 GB; 3D data: 60–80 GB**, depending on the specific PDE and parameters.
- **License**: **the dataset is licensed under CC BY** (Appendix K.6, p.49, explicit statement: *"The dataset is licensed under CC BY license."*). Code is released "under a permissive open source license" (p.2) — the exact code license isn't spelled out in the extracted text beyond this general statement, but per-file license notices are said to be included in the repository (Checklist, p.11–12).
- **Provenance/creation**: dataset generated early-to-mid 2022, by the paper's authors (with acknowledged help from ANU Techlauncher students for code/design consulting), funded in part by the DFG under Germany's Excellence Strategy grant EXC 2075 – 390740016 (SimTech). No personal/human-subject data is involved anywhere (explicitly confirmed through the entire "Composition"/"Collection Process" ethics checklist in Appendix K.2–K.3, p.45–47 — all answers are "No"/"N/A").
- **Known composition caveat, explicitly stated** (Appendix K.5, p.48, Q4): the 3D datasets have only **100 samples**, much smaller than the 1D/2D datasets' 1,000–10,000, purely because of storage limits and the very large size of individual 3D samples — flagged as a possible source of insufficient training data / accuracy for 3D models, though "realistic for scientific simulations" where a single high-fidelity data point can be expensive. The authors' mitigation: full data-generation source code is released so users can generate more 3D samples themselves if needed.
- **Reproducibility**: pretrained baseline models are also hosted on DaRUS (Appendix K.8, p.50) so users can validate the paper's own reported numbers or continue training from the released checkpoints.

### 2.12 Stated limitations and open problems (Section 5 "Conclusions and Limitations", p.10; scattered caveats throughout Section 4 and appendices)

- Explicit, top-level limitation (p.10): the benchmark's scope is intentionally restricted to **time-dependent PDEs for flow-type problems**; it does **not cover other physics domains or quantum mechanics**, and within flow problems specifically it does **not yet cover multi-phase flows or non-rectangular domains** — both named as future work.
- The paper explicitly states its own headline finding as a kind of meta-limitation of the field, not just of PDEBench: *"the standard error measure in ML, the RMSE on test data, is not a good proxy for evaluating ML models, in particular in turbulent and non-smooth regimes where it fails to capture small spatial scale changes"* (p.3, echoed p.2). This is the entire justification for the paper's expanded metric suite (cRMSE, bRMSE, fRMSE).
- PINN cannot be applied at all to Darcy flow (task structure incompatible with the DeepXDE PINN formulation) and was not run on 2D/3D compressible NS due to GPU memory limits (p.8, footnote 6) — a hard capability gap, not merely a worse score.
- FNO's Fourier-space representation has a **hard architectural ceiling on representable spatial frequency**, producing Gibbs-phenomenon-like blow-ups near shocks/discontinuities — demonstrated quantitatively via the two-order-of-magnitude jump in fRMSE-high as diffusion coefficient decreases in Burgers' (Section 4.2).
- U-Net trained naively (fully autoregressive, no stabilization) is **unstable under rollout** — a core finding requiring the pushforward-trick workaround (Section 4.3).
- Neural surrogates (tested via FNO on Advection/Burgers) **do not reliably extrapolate in time** beyond their training horizon — error grows monotonically past the trained window (Section 4.3, Figure 5c) — explicitly called "a challenging task" for present ML models.
- The apparent 3D-inviscid-easier-than-2D-inviscid CFD result is flagged by the authors themselves as likely an artifact of the 3D dataset's lower resolution producing artificially smooth training data, not evidence that 3D physics is genuinely easier — and they draw the general lesson that **high-resolution training data is required for real-world high-Reynolds-number problems** (Section 4.2, p.8).
- The "ground truth" itself is only as good as the discretization used to generate it — Appendix H's resolution-sensitivity experiment shows that at 128×128 the *simulator's own* discretization error can rival or exceed the neural surrogate's prediction error, and the authors explicitly say further work is needed to know whether their chosen "high resolution" reference (512×512) is fine enough to trust as ground truth (p.23).
- Small 3D sample count (100 samples) explicitly flagged as a possible accuracy bottleneck (Appendix K.5, p.48).
- The runtime comparison between classical solvers and ML methods is explicitly caveated as not fully "fair" because the method classes are optimized for different hardware setups (footnote 8, p.9: *"Whether or not this constitutes a fair comparison is surely debatable."*) — a rare and useful example of a benchmark paper being self-critical about its own headline speed claims.
- No societal-impact concerns are claimed (Checklist, p.11), and the dataset review confirms no personal/sensitive data anywhere in the benchmark.

### 2.13 Teachable moments (PDEBench)

- **RMSE alone is a bad report card for PDE surrogates.** This is the single most important lesson of the paper and should anchor any lecture on evaluating neural PDE solvers: a model can have excellent bulk RMSE while completely failing to conserve mass/momentum, getting the boundary condition wrong, or being unable to resolve the high-frequency (fine-scale/turbulent) content of the solution. The fRMSE-by-band decomposition and cRMSE/bRMSE metrics are worth teaching as a template metric suite for *any* physics-emulation task, not just this benchmark.
- **A common misconception the paper directly corrects**: that Fourier Neural Operators, because they are the strongest general baseline here, are close to a universal solution for PDE surrogate modeling. The Gibbs-phenomenon failure near shocks and the systematic FNO-loses-to-U-Net result on Darcy flow (attributed to task similarity to U-Net's native image-denoising domain) both show that "best on average" does not mean "best on every task," and architecture-task fit still matters enormously.
- **CFL-condition intuition, made concrete**: the resolution-scaling experiment (Appendix G) is a clean, quantitative way to teach why classical explicit solvers get *slower* as physical diffusion/viscosity increases (Δt ∝ Δx²/η) while a trained neural surrogate's inference cost is essentially flat regardless of viscosity — a genuinely surprising inversion of intuition ("shouldn't the harder physics take the network longer too?") worth pausing on in a course.
- **Autoregressive rollout instability and the pushforward trick** is a second worked example (alongside MeshGraphNets' noise injection in Part 1) of the general problem that training on one-step prediction does not guarantee stable long-horizon rollout — a foundational issue for anyone building any autoregressive physics emulator, not specific to U-Net.
- **PINNs are not drop-in emulators.** The requirement to retrain per-sample (no amortization across initial/boundary conditions) and the outright inapplicability to Darcy flow's operator-learning-style task are concrete, teachable boundaries of what a PINN can even represent — good for correcting the common assumption that PINNs are "just another neural network you can point at any PDE."
- **Ground truth is not free of error.** Appendix H's finding that a low-resolution "ground truth" simulation can be less accurate than a well-trained neural surrogate evaluated against a *higher*-resolution reference is a subtle but important point: benchmark numbers are only as trustworthy as the discretization used to generate the reference data, and this should be raised whenever students compare an ML surrogate's error against "the simulator" without asking what resolution that simulator itself was run at.
- **The turbulence result** (FNO and U-Net converging/tying specifically in turbulent-IC compressible NS cases, versus FNO's usual large lead in smooth cases) is a good discussion prompt: turbulence's broadband, non-smooth spectral content appears to erase architectural advantages that show up clearly on smoother problems — tying back neatly to the fRMSE-band metric that made this visible in the first place.
- Quote (p.3): *"There is no one-size-fits-all model and there is plenty of room for new ML developments."*
- Quote (p.9): *"present ML models cannot properly capture the dynamic behavior of the PDEs, and it is a challenging task to provide reliable predictions beyond the time experienced during training."*
- Quote (p.10, Limitations): *"With respect to flow problems, our main limitations are that we do not yet cover multi-phase flows or non-rectangular domains."*

## PART 3 — Cross-paper connections worth teaching together

- Both papers converge on the same core problem — **how to make a one-step-trained neural network stable over long autoregressive rollouts** — and offer two different named techniques for it: MeshGraphNets' training-noise injection (MGN p.5, p.14–15) and PDEBench's pushforward-trick-trained U-Net (PDEBench p.9). Worth presenting side by side as two solutions to the same underlying instability, one on irregular meshes and one on regular grids.
- MeshGraphNets operates natively on **irregular, adaptive meshes** and treats mesh-resolution independence as a first-class design goal (Section 3.2 remeshing, Section 5 generalization-to-scale experiments); PDEBench's baselines (FNO, U-Net) operate on **fixed regular grids**, and PDEBench's own results (Darcy Flow, diffusion-sorption boundary conditions) repeatedly show these grid-based methods struggling exactly where irregular geometry, non-trivial (Cauchy/Dirichlet/Neumann) boundary conditions, or spatially heterogeneous parameters are involved — the two papers can be read as complementary evidence for *why* mesh-based / geometry-aware neural PDE solvers (MGN's approach) are an active alternative to the grid-based Neural-Operator mainstream that PDEBench primarily benchmarks.
- Both papers report large (1–3 order of magnitude) **inference speedups vs. classical solvers** (MGN Table 1/A.5.1, PDEBench Section 4.4/Appendix G) but both are careful to note the comparison's fairness is complicated by mismatched hardware optimization between classical solvers and neural network inference (MGN p.17: "we find it hard to provide a 'true' hardware-agnostic performance comparison"; PDEBench p.9 footnote 8: "Whether or not this constitutes a fair comparison is surely debatable.") — a good example of methodological honesty worth flagging to students as the standard they should hold their own speedup claims to.
- Neither paper's core baseline overlaps directly (MGN doesn't test FNO; PDEBench doesn't test graph-based mesh methods), so a natural assignment/discussion question is: how would MeshGraphNets' architecture likely perform on PDEBench's Darcy Flow or diffusion-sorption tasks, given its strengths (irregular BCs, spatial heterogeneity) as documented in each paper?
